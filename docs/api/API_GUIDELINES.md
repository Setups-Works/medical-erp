# REST API guidelines

Base path `/api/v1`. JSON, UTF-8. The OpenAPI spec is generated by springdoc and committed at `contracts/openapi/meno-api.yaml`; the TS client in `packages/api-client` is generated from it.

## URLs

- Plural nouns, kebab-case: `/api/v1/sales-invoices`, `/api/v1/items/{id}/batches`.
- Actions that aren't CRUD are sub-resources with verbs: `POST /sales-invoices/{id}/post`, `POST /purchase-invoices/{id}/reverse`.
- Platform admin: `/api/v1/platform/*`. Sync: `/api/v1/sync/*`.

## Headers

| Header | Use |
|---|---|
| `Authorization: Bearer <jwt>` (desktop) or `meno_at` HttpOnly cookie (web) | Auth |
| `X-Branch-Id` | Active branch; validated against token |
| `Idempotency-Key` | Required on POST that creates/posts money or stock documents |
| `Idempotent-Replayed: true` (response) | Set when a repeated `Idempotency-Key` returns the stored original response (same status and body; ADR-0009) |
| `X-Request-Id` | Optional; echoed and logged (generated if absent) |
| `If-Match` | Optimistic concurrency for updates (ETag = version) |

## Responses

Success — resource directly for single items; lists use a page envelope:

```json
{ "items": [ … ], "page": 0, "size": 25, "totalItems": 312, "totalPages": 13 }
```

> The base plan proposed a `{success, message, data}` wrapper for every response. We use plain resources + standard HTTP status + Problem Details for errors instead (ADR-0009), because generated clients and caching handle that more cleanly. Messages for the user are built in the UI.

Errors — RFC 9457 Problem Details:

```json
{
  "type": "https://meno.app/problems/batch-expired",
  "title": "Batch expired",
  "status": 422,
  "detail": "Batch B123 of Dolo 650 expired on 2026-03-31.",
  "code": "INVENTORY_BATCH_EXPIRED",
  "errors": [{ "field": "lines[2].batchId", "code": "EXPIRED" }],
  "requestId": "01J…"
}
```

Status codes: 200, 201 (+ `Location`), 204, 400 (malformed), 401, 403 (no permission), **404 (not found or other tenant)**, 409 (version conflict / duplicate), 422 (business rule), 429, 500.

Error `code`s are `MODULE_REASON` in UPPER_SNAKE and listed per module in its `AGENTS.md`.

## Data formats

- Money and quantities as **strings** in JSON (`"123.4500"`) to avoid float issues; TS parses with decimal.js.
- IDs: UUID strings. Dates `yyyy-MM-dd`; timestamps ISO-8601 UTC.
- Enums: UPPER_SNAKE strings.

## Lists

`?page=0&size=25&sort=docDate,desc&q=dolo&status=POSTED&from=2026-04-01&to=2026-04-30`. Max size 200. Reports may stream CSV/XLSX via `Accept`.

## Versioning

Additive changes stay in v1 (new optional fields, new endpoints). Breaking changes → `/api/v2` for that resource, v1 kept for 2 desktop release cycles (desktop clients update slowly).

## Security

Every endpoint declares a permission: `@RequiresPermission("sales.invoice.create")`. Rate limits: auth endpoints 10/min/IP, general 300/min/user (Nginx + Redis).
